QuizAI: an AI-powered quiz platform for classrooms

Teachers create quizzes in seconds, either by typing questions or by uploading a PDF that AI turns into multiple-choice questions. Students take timed quizzes, get instant scored feedback with explanations, and can ask an AI tutor when they're stuck.

The problem it solves

Writing quizzes takes time

Turning a chapter of notes into good multiple-choice questions can take a teacher an hour. QuizAI drafts them from a PDF in under a minute. The teacher then reviews and edits them.

Grading is repetitive

Every submission is scored automatically on the server, and the teacher gets a ranked leaderboard they can export to Excel.

Students need feedback

Right after submitting, students see which answers were right or wrong and why, and they can ask the AI tutor follow-up questions.

Who uses it

Teacher

Creates and tracks

Creates batches (classes), builds quizzes manually or with AI, sets a deadline and time limit, and follows results on a dashboard and leaderboard.

Student

Joins, attempts, learns

Joins one or more batches, sees which quizzes are available, completed or overdue, takes timed quizzes, reviews results and chats with the AI tutor.

How it's used, step by step

Teacher journey
  1. Register as a teacherYou are logged in straight away.
  2. Create a batchFor example, "CS-A 2025". Students will look for this name.
  3. Create a quizType the questions on Create Quiz, or upload a PDF on Upload Material and let Gemini draft them.
  4. Review and publishFix any AI mistakes, choose the correct answers, set the deadline and duration, then publish.
  5. Track resultsThe dashboard shows averages and submissions. The leaderboard filters by batch or quiz and exports to Excel.
Student journey
  1. Register as a studentThen open Batches.
  2. Join a batchPick your teacher's batch from the list.
  3. Start a quizFrom the dashboard or Active Quizzes. A countdown timer starts.
  4. SubmitManually, or automatically when the time runs out. Each quiz can be taken only once.
  5. Learn from the resultSee your score, correct answers and explanations, then ask the AI tutor about anything unclear.

How it works

QuizAI is a classic three-tier web app. The React frontend runs in the browser and talks to an Express REST API. The API stores everything in MongoDB, keeps frequently read data in a Redis cache, and calls Google Gemini for the AI features.

What happens when a teacher uploads a PDF

  1. UploadThe PDF is sent as multipart/form-data. Multer keeps it in memory, accepting PDFs up to 10 MB.
  2. Extract textpdf-parse reads the text. Scanned, image-only PDFs are rejected with a clear message.
  3. Ask GeminiThe text and a strict prompt go to Gemini in JSON mode, asking for N questions with 4 options, the correct index and an explanation.
  4. ValidateThe server parses the JSON and drops any malformed question before showing a preview.
  5. Teacher reviews, then publishesNothing is saved until the teacher clicks Publish.

What happens when a student submits

  1. Answers onlyThe browser sends only the chosen option indexes and the time spent, never a score.
  2. Server-side scoringThe API checks that the student belongs to the batch, scores the answers against the stored correct answers and saves a Result.
  3. One attemptA unique database index on (quiz, student) makes a second submission impossible.
  4. Fresh dataRelated cache entries are cleared, so the dashboard and leaderboard update immediately.

What data it stores

User

name, email (unique), hashed password, role (student or teacher), list of joined batches

Batch

name (unique), teacher, list of students. A class or group.

Quiz

title, batch, creator, source (ai or manual), deadline, duration, average score, and its questions (text, options, correct index, explanation)

Result

quiz, student, score, number correct, time spent, the chosen answers. One per student per quiz.

Run it on your machine

You need Node.js 18+ and MongoDB, either locally or on a free MongoDB Atlas cluster.

# Backend
cd backend
cp .env.example .env      # set MONGO_URI, JWT_SECRET and (for AI) GOOGLE_API_KEY
npm install
npm run dev               # API on http://localhost:5000, docs on /api-docs

# Frontend (second terminal)
cd frontend
npm install
npm run dev               # open http://localhost:5173
Tip: Everything except Ask AI and Generate quiz from PDF works without a Gemini key. Get a free key at aistudio.google.com. Redis is optional too. Or run the whole stack with docker compose up --build and open http://localhost:3001.

Try it: register a teacher in one browser and a student in a private window. As the teacher, create a batch and a quiz. As the student, join the batch and take the quiz. Then check the teacher's leaderboard.

Glossary

Batch
A class or group of students owned by one teacher. Quizzes are assigned to a batch.
Active quiz
A quiz in one of your batches that you haven't taken yet and whose deadline hasn't passed.
Overdue
The deadline passed before you attempted it, so it can no longer be started.
Duration
The time limit in minutes once a quiz is started. It auto-submits at zero.
JWT
JSON Web Token. A signed token proving who is logged in, stored in a cookie.
Cache invalidation
Deleting cached data when the underlying data changes, so users never see stale numbers.
Swagger
An interactive web page listing every API endpoint, available at /api-docs.

FAQ

Can a student see the correct answers before submitting?

No. The quiz endpoint for students strips the correct answers, and scoring happens only on the server. Answers are revealed on the result page after submitting.

Can a student retake a quiz?

No. Each student can submit each quiz once. This is enforced by a unique database index.

Is the AI always right?

Not always. That's why AI-generated quizzes open in an editable preview: the teacher can fix wording, change the correct option or remove a question before publishing.

What if Redis isn't available?

The app falls back to an in-memory cache automatically, so it keeps working.

Where is the API documented?

At /api-docs on the backend (Swagger UI), and summarised in the README.
